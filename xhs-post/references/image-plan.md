# 配图决策流程

> **铁律：先选方向做计划，再落地。不要收到需求就去生成图片。**
>
> 理由：配图返工成本远高于文案，而文风决定配图风格、配图风格决定配图数量——顺序错了会全盘重来。

---

## 三步，顺序不能颠倒

```
第一步  这篇用什么类型的图？   → 实拍 / 生成 / 网页渲染 / 现成截图
第二步  几张图，各讲什么？     → 分工表，一张图讲一件事
第三步  每张图怎么落地？       → 按类型分流，见下
```

第一步和第二步的结果必须**在 PLAN 阶段交人确认**，确认后才做第三步。

---

## ⚠️ 大多数配图不需要外部画风 skill

**先确定最优配图方案，该用 skill 就用，不需要就不用。** 不要一上来就去 registry 里找 skill——那是本末倒置。

实际比例大致是：

| 情况 | 占比 | 怎么做 |
|---|---|---|
| 实拍图 / 现成截图 | 多数 | `photo-real`，出制作指导，**完全不涉及 skill** |
| 参数表、备忘录、产品卡 | 常见 | 内置的 `spec-table-card` / `ios-memo` / `product-card` 等固定图式 |
| 需要特定美学质感 | 少数 | 才去 `styles.registry.json` 找对应画风 |

外部 skill 解决的是"我要一种做不出来的视觉风格"，不是"我要一张图"。

---

## 第一步：选图片来源

| 来源 | 什么时候用 | 产出什么 |
|---|---|---|
| **实拍图** | 素人体、场景型卖点、需要真实感 | **不出 prompt**。出「制作指导」+「图上要用的文本」 |
| **网页渲染**（html-screenshot） | 参数表、多字备忘录、任何有具体数值的图 | 结构化 `content`，CSS 渲染，文字像素级精确 |
| **模型生成**（image-gen） | 氛围封面、无实拍素材的场景图 | 完整 prompt，含精确文字 + `text_on_image` 核对清单 |
| **现成截图** | 电商榜单、App 界面、聊天记录 | 指明截什么、需要遮挡/脱敏哪些区域 |

### ⚠️ 实拍图不要出 prompt

这是最容易做错的地方。如果这张图是实拍，模型的工作**不是描述一张不存在的图**，而是告诉人怎么把已有的照片变成配图：

```markdown
图3 · 实拍 · 露天车位淋雨实拍
制作指导：
- 用现有的露天安装照，取桩体正面 + 雨痕可见的角度
- 左上角加 📍 emoji + 白色描边大字「露天装了半年」
- 右下角加半透明白底文字块，放三行参数
图上文本：
- 大字：露天装了半年
- 参数块：桩体 IP65 ／ 枪头 IP67 ／ 26重防护
```

**虽然不生成图，但图上要用的文本仍然由模型产出**——这部分是文案工作，不是美工工作。

---

## 第二步：分工表

一张图讲一件事。塞不下就拆，**不要缩字号**。

张数经验值见 `platform-rules.md`。分工表格式：

```markdown
图1 封面 · [风格] · [一句话说明这张图要达成什么]
图2 [角色] · [风格] · [讲什么]
...
```

封面单独决策，见 `cover.md`。

---

## 第三步：按来源落地

### 网页渲染（html-screenshot）

结构化内容填进 `images[].content`。`spec-table` 和 `product-card` 是**固定字段结构**——字段集和顺序不可变，这样才能：
- 自动比对产品 xlsx，执行「参数必须来自知识库」
- 自动执行「不暴露降配」（`*牛`耐压只写终值、雷*恩内存不输出）
- 复写时字段不漂移

其余图式自由结构。

### 模型生成（image-gen）

prompt 模板见 `../vendor/` 下对应画风，或用通用模板：

```
A [风格描述] Xiaohongshu style infographic card, vertical 3:4 aspect ratio.

LAYOUT:
- Top: main title in large bold Chinese text reading "「主标题」"
- Below: subtitle reading "「副标题」"
- Middle: [产品图位置 / 表格 / 要点列表]
- Each row: [图标] icon on the left, Chinese text reading "「要点文字」"

STYLE:
[配色、材质、字体感觉]

CONSTRAINTS:
Render all Chinese text crisply and accurately. No competitor logos, no watermarks,
no extra text beyond what is specified.
```

要点：
- **文字用引号原样写出**，并说明位置和层级
- 比例写 `vertical 3:4 aspect ratio`
- 单图中文 ≤ 80 字，超了拆图
- 需要人工贴实拍产品图的，在 prompt 里指明留白区，并填 `images[].reserved_area`
- 必须同时产出 `text_on_image` 清单——**生图模型会写错字，这份清单是交付后逐条核对的依据**

### 现成截图

指明：截哪个页面、需要遮挡什么（订单号、真实姓名、618 字样）、是否需要脱敏品牌名。

⚠️ **618 常常藏在电商截图里**，见 `compliance.md` 第 1 节。

---

## polish：精致不等于好

`polish` 决定看起来精不精致，**与 render_mode 无关**——HTML 完全可以渲染出很土的备忘录截图，且文字还准。

| polish | 用在 | 反例 |
|---|---|---|
| `pgc-polished` | `hardcore-review` `persona-match-review` 等专业体 | 素人体用它 = 一眼广告 |
| `ugc-raw` | `nanny-guide` `first-person-journey` `head-to-head` 等第一人称体 | 参数对比表用它 = 看不清 |
| `mixed` | 同一篇里分图使用 | — |

`mixed` 是常态而非例外。样本行 8 就是：参数大表规整（pgc）+ 产品图实拍叠字（ugc）+ 榜单直接用电商截图（ugc）。**单张图可用 `images[].polish` 覆盖整篇设置。**

⚑ 「第一人称体应走 ugc-raw」是推断。转化数据只覆盖了文风轴，没覆盖配图轴。

---

## 出图后必查

```
□ 比例 3:4（1080×1440）
□ 中文逐字校对，重点核参数数字（IP65/IP67、5000V、26重 错一位就是事故）
□ 品牌名已脱敏（雷*恩 / *牛 / *达 / *想 / *米 / *斯拉 / *亚迪），型号保留全称
□ 无 AI 生成的竞品产品外观、logo、内部结构
□ 无水印、无原作者名
□ 无 618（含截图素材内）
□ 封面标题与正文标题一致（若做过查重改写需同步）
```

参数错了就改 prompt 重出，**不要将就**。
