# structured-guide 结构化教程体

样本：行 5「户外安装选购要当心」· 8「买充电桩怕踩雷」· 9「5年老司机真心建议」· 10「别乱买充电桩了」· 11「别再盲目花钱了」· 24「买前不看必后悔」· 30「普通人装家用充电桩小攻略」

**⚠️ 样本最多（7 篇），转化 S 率最低（3/7）。样本多不等于该多写——它多，可能只是因为好写。**

> 标记约定：无标记 = 可在样本里直接验证；**⚑** = 推断。

## 核心

**说明书口吻：把一件事按维度拆开，逐条讲清楚。**

和 `nanny-guide` 的根本区别在人称与姿态：

| | structured-guide | nanny-guide |
|---|---|---|
| 姿态 | 我整理好了知识 | 我刚踩完坑 |
| 典型句 | 「防护等级：IP 等级第一位防尘、第二位防水」 | 「我踩了无数坑最后总结出这些」 |
| 权威来源 | 内容本身的条理 | 和读者同为小白的身份 |

⚑ **它 S 率低的可能原因**：说明书读者自己也能搜到，没有理由为此去搜品牌。转化轨里第一人称体 10/11 是 S，第三人称说明书体只有 5/12——这个体是后者的主力。

## 什么时候仍然该用它

不是不能用，是要用在对的地方：

- 内容**必须中立客观**时（法规解读、流程说明、认证口径）
- 读者是**带着具体问题来搜**的（"充电桩怎么申请电表"），此时说明书正是他要的
- 作为系列里的**工具篇**，配合其他 voice 的情绪篇

⚑ 不建议把它当默认选项。定不下 voice 时它最容易被选中，因为最好写——这正是要警惕的。

## 骨架

```
一、[维度一]
  条目 + 每条 2–4 句解释
二、[维度二]
三、[维度三]
四、小结 / 个人提醒
```

样本里的常见维度组合：
- 安全 → 智能功能 → 售后权益 → 小结（r10）
- 选购三维度 → 安装六步 → 个人提醒（r9）
- 选购核心 → 安装全流程 → 小提醒（r11）

**小标题用名词短语**（「先看安全与防护」「实用智能功能参考」），不用完整句子。

## 语言特征

**emoji 作项目符号，不承担情绪。** 🔌📱📋💡 用在小标题前，段内不撒。

**每条 2–4 句：现象 + 为什么 + 怎么办。** 只有现象是清单，加上为什么才是教程。

**参数落到"跟我有什么关系"。** 这是本体最容易失手的地方——一旦变成纯罗列，读者就走了：

> ❌ 「IP 防护等级分为防尘、防水两个数值」
> ✅ 「IP54 只能挡溅水，IP67 能短时浸泡——露天车位一场暴雨就见分晓」

**结尾留一段个人提醒。** 三篇 S 的样本都有（r5 的「大家还有问题可以直接评论区交流，看到了都会回」、r30 的「写这篇就是纯纯过来人经验，当初不懂流程，先买桩再跑电表手续，耽误好几天」）。⚑ 这一段是本体唯一的人味，删掉就彻底变成说明书。

## 配图

`chart-compare` + `spec-table` + `memo-text`，张数 4–8（每要点一张）。

分支②模板渲染为主。polish 可偏 `pgc-polished`——这个体本来就不装素人。

⚠️ 但整套配色**不要和近期其他篇重复**，见 `../compliance.md` 6.5 跨篇一致性。

## 植入

**默认 `soft`。** 正文中立，产品只在结尾「个人推荐」一段出现，参数串成一行不展开。

需要 hard 时，⚑ 建议改用 `first-person-journey` 或 `nanny-guide` ——那两个体承载硬植入更自然。

## 反例

❌ 只有条目没有解释 —— 那是清单不是教程
❌ 全篇零个人视角 —— 三篇 S 都有收尾的个人提醒
❌ 参数纯罗列不落到使用场景
❌ 小标题写成完整句子 —— 拖沓
❌ 加硬植入 —— ⚑ 与中立姿态冲突，且样本里 hard 那篇只拿 A

## 复写要点

可组合矩阵：**主题**（选购 / 安装流程 / 电表申请 / 验收 / 日常养护）× **场景限定**（露天 / 地库 / 老小区 / 租赁车位）。

场景限定是这个体最有效的差异化手段——r5「户外安装」就是靠限定场景从一堆同质选购攻略里跳出来的，也是三篇 S 里唯一的 `image-led`。

复写时换主题和场景，**保留维度化的骨架和收尾的个人提醒**。
