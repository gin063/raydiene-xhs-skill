# 工作流 · 爆文复写

**输入**：原文全文 + 原文配图
**输出**：同骨架、不查重的新笔记（MD + 配图）

和写新内容的根本区别：**结构是给定的，你的工作是在保住有效结构的前提下换掉所有可被判重的表层。**

---

## 复写的唯一判定标准

> **结构相似即可，表层必须全换。**

不是"写得像"，也不是"写得不像"。是：
- 骨架保留 —— 这是爆款之所以爆的原因，扔了就白复写
- 措辞、案例、数字表述、配图细节全换 —— 这是查重的判定面

---

## 阶段一 · 拆解原文（先拆，不要先写）

读完原文全文和配图，输出一份拆解：

```markdown
## 原文拆解

**1. 骨架**（必须保留）
段落顺序 + 每段的功能，不是内容。
例：自嘲钩子 → 痛点 → 利他承诺 → 编号流程×4 → 产品参数串 → 收尾鼓励

**2. 有效钩子**（保留机制，换表达）
原文用了什么手法抓人：自嘲 / 数字 / 冲突 / 反直觉。
保留手法，换掉具体那句话。

**3. 表层清单**（全部要换）
- 具体措辞与句式
- 举例、场景、金额、时间
- emoji 的具体选择
- 标签组合
- 配图配色与细节

**4. 三轴判定**
voice / placement / body_carries — 从原文反推，复写时保持一致。
若在 templates.json 里能查到该模板编号，直接取已标注的值。

**5. 卖点**
原文打的是哪个卖点？复写要不要换？
换卖点会改变行文逻辑，属于「改编」不是「复写」——需要先确认。
```

## 阶段二 · 正文复写

### 换的方法

| 层 | 怎么换 |
|---|---|
| 措辞 | 同义替换 + 换句式（主动↔被动、陈述↔疑问、长句拆短） |
| 案例场景 | 换一个同类场景（地库→露天、邻居→同事、618→日常） |
| 数字表述 | **参数值不动**，换表述方式（"900多" ↔ "不到一千" ↔ "八百多"） |
| emoji | 换一组，保持密度和位置功能不变 |
| 标签 | 保留 2–3 个核心词，其余换 |

### ⚠️ 数字类承诺要从内容数出来

标题、封面、正文里的「28个坑」「30件事」这类数字，**必须是数出来的，不能先定后凑**。

2026-08-19 实测：标题和封面都写 28，实际渲染 29 条——先编了数字再让内容去凑，两边同时错，而且自查时看不出来（两边一致，只是都错）。

在 `cards.json` 里声明 `claimedTotal`，渲染脚本会替你比对：

```
❌ 条目数不符：cards.json 声明 28 条，实际 29 条。
```

### ⚠️ 参数值不动

同义替换只作用于**表述**，不作用于**参数**。IP65 不能改成 IP66，5000V 不能改成 4800V。参数来源永远是产品 xlsx。

### 标题

仍然给 **≥3 个候选**，全部 < 20 字，且与原标题都不重复。原标题的钩子手法可以保留，具体措辞必须换。

## 阶段二点五 · 去 AI 味

同 `../humanize.md`。

⚠️ 复写场景有个冲突要注意：Humanizer 判定「刻意换词」是 AI 痕迹，但**复写的同义替换是为了过查重**。两者目的不同——复写时以过查重优先，只在同一段内反复换同一个词时才按 AI 痕迹处理。

## 阶段三 · 配图复写

### 封面：小改，不重做

原封面的构图和视觉记忆是爆款资产的一部分，重做等于扔掉。

| 可改 | 不改 |
|---|---|
| 主色/辅色（换一套配色） | 整体构图与分区 |
| 字体、字重 | 元素相对位置 |
| 图标、emoji 的具体选择 | 信息层级 |
| 文案措辞（同义替换） | 大字位置与字号关系 |
| 产品图角度/裁切 | 产品数量与排布方式 |

**原则：扫一眼像同一个系列，逐帧比对是两张图。**

### 内页：改动幅度可以比封面大

内页不承担点击率，可以换配色、换图标组、调整卡片顺序、替换实拍角度。

### ⚠️ 封面标题必须与正文标题同步

复写时正文标题改了，封面上的大字也要改。这是最高频的疏漏——两边不一致会显得很业余。

## 阶段三点五 · 机器查重（不能只凭自评）

```bash
python xhs-post/scripts/validate_post.py <交付.md> --against <原文.txt>
```

只比**汉字**——标点数字英文在改写中天然会保留（参数值本来就不许动），算进去会淹没真正的照搬。命中会报出最长重合串。

⚠️ **人工自评在这件事上不可靠。** 2026-08-19 首次复写实测：自查清单里给「正文无整句照搬」打了勾，机器一跑出来 3 处，最长一处 19 个字。**凭印象读一遍是查不出照搬的**——尤其参数串和收尾这种"感觉已经改过了"的地方。

高频重合位置：
| 位置 | 为什么容易照搬 |
|---|---|
| 产品参数串 | 参数值不许动，顺带把连接词和顺序也留下了 → **拆成分句、重排顺序** |
| 收尾建议句 | "按你的预算和车位环境定"这类话就那么几种说法 → 换主语和句式 |
| 植入外壳句 | "第一次装、不想啃参数的" → 换人称词 |

## 阶段四 · 合规复查（复写不能跳过）

复写最容易漏掉合规，因为"原文能发说明没问题"。**这个假设不成立**：

1. **原文可能本来就踩线**，只是没被查到
2. **监管口径会变**（3C 强制时间、GB 标准实施日）
3. **脱敏规则已变更**——2026-08-18 起雷迪恩本品也要脱敏为 `雷*恩`，早期原文里是全称
4. **618 等限流词**在原文和原配图里都可能存在

### 🔴 多品牌推荐体的陷阱（复写最高频翻车点）

若原文是**同一品牌的产品线**（可以"强推每一款"），而复写要改成**多个品牌含竞品**，**不能照搬"强推/闭眼冲"的口吻——那等于给竞品带货。**

必须改成纯对号入座，只有雷*恩用带温度的口吻。

完整清单见 `../compliance.md` 第 9 节，逐条过。

## 交付

格式同 `new-post.md`，额外加两节：

```markdown
## 六、复写对照
| 层 | 原文 | 本篇 |
|---|---|---|
| 标题 | … | … |
| 钩子 | … | … |
| 案例场景 | … | … |
| 封面改动 | — | 配色 X→Y、图标组更换、文案同义替换 |

## 七、查重（机器验，不能只凭自评）
```bash
python xhs-post/scripts/validate_post.py <交付.md> --against <原文.txt>
```
□ 标题与原文无连续 8 字重合
□ 正文与原文无连续 8 汉字重合（**上面的命令跑出 OK 才算数**）
□ 段落顺序保留，措辞全换
□ 封面构图保留，配色/字体/文案已改
□ 封面大字与新标题一致
□ 标签组合已更换（保留 2–3 核心词）
```

「复写对照」这一节的作用是留痕——下次复写同一模板时，能看到前几次改了什么，避免撞车。
