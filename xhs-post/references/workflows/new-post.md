# 工作流 · 写新内容

**输入**：一个标题 + 粗略结构概况（有时只有一句话）
**输出**：一份 MD（标题候选 ≥3 + 正文 + 配图方案 + 合规自查 + 待确认）+ 配图文件

---

## 阶段一 · PLAN（必须交人确认后才能往下）

**收到需求不要立刻写正文，更不要立刻生成图片。**

先读 `3C充电桩对比产品信息-更新至260731.xlsx`（定位到文件名日期最新的版本），找到相关产品列，抽出本篇要用的字段。空值写「未标注/以官方为准」，**不得推测填充**。

然后输出一份不超过一屏的方案：

```markdown
## PLAN

**1. 需求理解**
一句话：这篇要解决什么、给谁看、要读者做什么。

**2. 轨道** → 转化 / 养号
（要人去搜品牌，还是要人关注这个号？）

**3. 主打卖点** → 选定：XXX
（从 selling-points.md 选，说明为什么是这个卖点。卖点决定行文逻辑和配图形式，先定它。）

**4. 文风 voice** → 选定：XXX
（从 voices/_index.md 选，说明为什么这个 voice 配这个卖点。附实测 S 率。）

**5. 植入强度 placement** → 建议：soft / medium / hard
（给建议 + 理由，不预设默认值。）

**6. 正文承载度 body_carries** → self-contained / image-led / image-only

**7. 配图方案**
主推画风：XXX ｜ 备选：XXX（各自优劣）
图1 封面：…
图2 …：…
（说明为什么是这个数量。张数经验值见 platform-rules.md）

**8. 需要先拍板的点**
（数据缺口、合规取舍、风格二选一。没有就写「无」。）
```

决策顺序是**卖点 → 文风 → 配图**，不能倒过来。卖点定不下来，后面全是猜。

---

## 阶段二 · DRAFT（正文）

确认 PLAN 后写正文。

### 标题：给 ≥3 个候选

按不同角度出，不要三个同义改写：

```
方案A（钩子型）：…
方案B（对号入座型）：…
方案C（痛点型）：…
```

每个都必须 **< 20 字**，写完实测字数。

### 正文要求

- **≤1000 字符**，目标 850 留余量。**含换行、含话题标签。** 写完实际统计并写在小标题上
- 开场 25 秒内给钩子，**别自我介绍**
- 短句为主，一句一个信息点
- 序号用 emoji（1️⃣2️⃣…），适量不滥用
- 参数落到「跟我有什么关系」，不罗列数字（见 `selling-points.md`）
- 结尾用**已有答案的诱饵**（"这三个问题我评论区都答过"），不用开放式提问——更能带评论
- **会公开发布的成品（正文、图上文本）用 ```publish 围栏标记**，其余代码块（自查清单、命令）不标。验证器只扫 publish 块——因为清单里会正常出现违禁词的描述

### 钩子强度必须匹配兑现能力

唯一的 B 级样本就死在这：标题承诺揭黑，正文只是三款参数卡。**兑现不了就换朴素钩子**——朴素钩子配足量干货，好过强钩子配空内容。

---

## 阶段二点五 · 去 AI 味（不可跳过）

正文定稿后、配图之前，按 `../humanize.md` 过一遍。

转化最好的是第一人称素人体，而 AI 写的第一人称最容易露馅——人设一塌转化就没了，且塌得无声无息。**注意那份小红书语境豁免清单**：emoji 密集和编号清单在小红书是常态，不要按通用规则清掉。

---

## 阶段三 · IMAGE PLAN（交人确认）

按 `image-plan.md` 三步走。**这一步产出的是方案，不是图片。**

确认要点：每张图的来源类型（实拍/渲染/生成/截图）、分工、风格。实拍图**不出 prompt**，出制作指导 + 图上文本。

---

## 阶段四 · RENDER

按 `image-production.md` 走对应分支：

| 分支 | 产出 |
|---|---|
| ① 现成模板 | 每张图的**完整最终文本**，独立 ```publish 代码块，换行即最终换行 |
| ② 模板渲染 | 填好的数据 + 调用说明，**可直接出图**（guizang 仅依赖 playwright，无 AI） |
| ③ 实拍图 | 用哪张/怎么拍 + 加什么(emoji/花字/文字块位置) + 图上文本 |
| ④ AI 生成 | 完整结构化散文 prompt（LAYOUT/STYLE/CONSTRAINTS）+ text_on_image |

出图后逐条过「出图后必查」清单。

## 交付

写到指定输出目录，**文件名纯 ASCII**（中文名会导致前端加载失败）。

```markdown
# noteXX · 标题 · voice

> PLAN 摘要（决策留痕：轨道 / 卖点 / voice / placement / 理由）
> 参数来源：3C充电桩对比产品信息-更新至260731.xlsx

## 一、标题候选（≥3）
## 二、正文 caption（XXX 字符）
```publish
（可复制正文）
```
## 三、配图方案与图上文案
## 四、合规自查（compliance.md 第 9 节清单逐条打勾）
## 五、待确认
```

「待确认」里每条都要是**真需要决策的事**（数据冲突、合规取舍、风格二选一），不要凑数。

---

## 协作习惯

- 小改动只贴改动块，不重写整个文件
- 缺料让人上传，**不自行编造或重建**
- 发现合规问题直接指出并给替代方案，不要默默绕过
- 发现参考原文有事实错误或逻辑问题（混淆监管时间点、帮竞品说话），**主动指出**
- 可以 push back。要的是判断，不是顺从
