# 平台硬约束

违反这些的产出无法发布或会被限流，与创意无关。🤖 = 已做进 `validate_post.py`。

## 文案 🤖

| 项 | 限制 | 说明 |
|---|---|---|
| 标题 | **< 20 字** | 硬上限。写完必须实测字数 |
| 正文 caption | **≤ 1000 字符**，目标 **850** | **含换行、含话题标签**。不要卡在九百多，留余量给后续微调 |
| 话题标签 | 不限量 | 样本实测 3–10 个，中位 7 |

字符数必须**实际统计后写进交付 md 的小标题**，不要凭感觉。

## 配图

| 项 | 值 |
|---|---|
| 比例 | **3:4** |
| 分辨率 | **模板渲染（分支②）固定 1080×1440**，CSS 需要具体像素；**AI 生成（分支④）不写死**，由模型决定，1086×1448 这类差异对小红书没有影响 |
| 单图中文字数 | **≤ 80 字**较稳，超过要拆图 |
| 首图 | 独立建模，见 `cover.md` |

密集文字（如长备忘录）即使模型能渲染，也建议拆成 2 张。**一张图讲一件事——塞不下就拆，不要缩字号。**

## 交付

- 文件名**纯 ASCII**。中文文件名（尤其含全角数字/符号）会导致前端 `Failed to load file content`
- 可复制的内容（标题、正文）一律放代码块

## 配图张数经验值

| voice | 建议张数 | 分工 |
|---|---|---|
| `hardcore-review` `persona-match-review` | 5–9 | 封面 + 维度卡 + 产品卡 + 结论卡 |
| `structured-guide` | 4–8 | 封面 + 每要点 1 张 |
| `nanny-guide` | 5–6 | 封面 + 3–5 张备忘录卡 |
| `first-person-journey` `head-to-head` | 4–6 | 封面 + 流程/对比实拍 |

| `body_carries: image-only` | 1–4 | 单张信息图讲完，或大表 + 产品卡 |
